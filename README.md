# KAiSEi PE SUGOROKU

体育やレクリエーションで使う、**お題の順位に応じてコマが進む、チーム対抗すごろくWebアプリ**です。運営者1人が操作し、1台のPCで完結します。プロジェクターを使う2画面モードにも対応しています。

## 実装済み機能

- 2〜12チーム：チーム名と色を自由に編集
- 1〜150マス：自動生成される折り返し型すごろく盤面
- 順位別移動量：前進・後退・移動なしに対応（例：1位 +5、2位 +3、3位 −1）
- お題登録：タイトル・説明・任意の制限時間・並べ替え・削除・途中追加
- お題ごとの専用移動ルール（未設定のお題は全体共通ルール）
- 登録順 / ランダム出題 / 運営者による手動選択。全お題を使い切ると自動で再利用（ラウンド履歴は保持）
- 順位入力：全参加チームに異なる順位を必ず割り当てる方式
- ゴール条件：最初のゴール・全チームゴール・運営者の手動終了
- 1画面モード：参加者向け表示と運営操作を同じPC画面に配置。発表表示も可能
- 2画面モード：表示専用ウィンドウを開き、PC画面とプロジェクターに分けて運営
- 公開制御：次のお題や入力途中の順位は、公開操作まで表示画面に反映しない
- 駒の移動アニメーション、進行履歴、結果表示
- 位置の手動修正、確定操作のUndo/Redo
- IndexedDBによる自動保存、JSONのバックアップ・復元
- PWAサービスワーカーによるオフライン再利用（最初のオンライン読み込みは必要）

## 起動方法

Node.js 22以上を推奨します。

~~~bash
npm install
npm run dev
~~~

画面に表示される開発用URL（通常 http://localhost:5173 ）をブラウザで開いてください。

~~~bash
npm test
npm run build
npm run preview
~~~

## 使い方

1. ホームから「新しいゲームを作る」か「サンプルで試す」を選ぶ。
2. チーム名・色、ゴールまでのマス数、終了条件、順位ごとの移動量を設定する。
3. 「お題」タブでタイトルと説明を登録。必要に応じて「このお題だけ移動量を変える」を有効にする。
4. ゲームを開始し、お題を選んで「このお題を公開する」を押す。
5. 実際の対決のあと、運営者が順位を矢印で並べ替え、「順位を確定・駒を移動」を押す。
6. 次のラウンドへ進む。お題をすべて使い切ると、自動的に全お題が再び出題対象になる（1巡中は重複なし）。途中追加もできる。
7. ゴール条件を満たすか「ゲームを終了する」で最終結果を表示する。

### 2画面モード

ブラウザの「2画面モード」をクリックすると、表示専用の別ウィンドウが開きます。このウィンドウを拡張ディスプレイのプロジェクター側に移し、全画面にしてください。運営者は元のウィンドウで操作します。

- 同じPC・同じサイトの2ウィンドウを **BroadcastChannel** で同期します。
- サーバー・ログイン・参加者用スマホは不要です。
- 別PCとの同期には対応していません。
- 表示ウィンドウを再度開くと、IndexedDBの公開用スナップショットから復元されます。
- ブラウザによってはポップアップの許可が必要です。

### ルールの補足

- チームごとの順位は **必ず一意** です。同順位の入力はありません。
- 進むマス数に負の整数を設定すると後退します。移動先は 0〜ゴール位置に制限されます。
- 「全チームゴール」では、ゴール済みのチームは次の順位入力に参加しません。
- 複数チームが同じラウンドでゴールした場合、そのラウンドの順位によって着順を決定します。
- 誤操作は「戻す」で取り消せます。設定の一般的なテキスト編集はUndo履歴の対象ではありません。
- 手動の位置修正はゲーム中に利用できます。修正後の位置は表示画面にも反映されます。
- ゲーム開始後、基本ルールとチーム構成はロックされますが、未実施のお題は追加・編集できます。
- 全お題の実施後は次のラウンドで自動的に新しい周回が始まります。登録順なら先頭から、ランダムなら未実施のお題から抽選します。過去のラウンド履歴は保持されます。旧バージョンの保存データで出題が止まっている場合は「お題をもう一巡する」で再開できます。

## データ保存と注意点

ゲームデータはこのPCの同じブラウザ・同じサイトの **IndexedDB** に保存します。ブラウザのサイトデータ削除、シークレットウィンドウ、別端末への移動では失われることがあります。大事なゲームはホーム画面から **JSONをエクスポート** してください。

JSONのインポートでは、同じ内容のゲームが別ゲームとして作成されます。取り込んだ進行中ゲームは安全のため「次のお題を選ぶ」段階から再開します。

PWAとしてのオフライン再利用には、事前にサイトを一度オンラインで読み込み、必要なファイルをキャッシュしておく必要があります。

## 技術構成

- Vite + React + TypeScript
- Zustand（状態管理）
- IndexedDB（ローカル永続化）
- BroadcastChannel（同一オリジンの2画面同期）
- CSS（盤面・UI・駒のアニメーション）
- Vitest（ゲームロジックの単体テスト）
- GitHub Actions（ビルド・テスト）

## リポジトリ構成

~~~text
src/
  App.tsx                   ホーム・画面遷移・表示専用ウィンドウ
  types.ts                 データモデル
  engine.ts                ゲーム進行・移動・ゴール判定
  engine.test.ts           ゲームロジックのテスト
  store.ts                 ZustandとUndo/Redo
  storage.ts               IndexedDB保存
  sync.ts                  2画面間のメッセージ通信
  styles.css               全画面のデザイン
  components/
    Settings.tsx           チーム・盤面・お題・移動量の設定
    Play.tsx               運営者の進行コントロール
    Audience.tsx           参加者向けの公開画面
    Board.tsx              すごろく盤面
public/
  sw.js                    オフライン再利用用サービスワーカー
  manifest.webmanifest     PWAマニフェスト
~~~
